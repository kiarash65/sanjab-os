# گزارش بازبینی کیفیت محتوای آموزشی و فنی SanjabOS

تاریخ بازبینی: ۲۴ نوامبر ۲۰۲۶  
شاخه: `main`  
هدف: اصلاح خطاهای تأییدشده در آموزش، متن فارسی، مرزبندی شبیه‌ساز و ورودی‌های API.

> این گزارش، یک دور بازبینی هدفمند است؛ ادعا نمی‌کند که تمام جمله‌های فارسی در هر ۳۸۳ مسیر مخزن به‌صورت انسانی بازنویسی شده‌اند. برای جلوگیری از تغییرهای پرخطر و بی‌پشتوانه، اصلاح‌ها به موارد قابل‌ردیابی و قابل‌آزمون محدود شده‌اند.

## اصلاح‌های انجام‌شده

### پایتون
- مثال الگوریتمی درس اول اکنون به‌عنوان «شبه‌کد فارسی» برچسب می‌خورد و دیگر با برچسب `python` نمایش داده نمی‌شود.
- چالش درس نخست به مفهوم‌هایی محدود شد که همان درس معرفی می‌کند؛ تمرین به‌طور ضمنی به `if/else` درس‌های بعد وابسته نیست.
- تفاوت «بایت‌کد»، «ماشین مجازی CPython» و فایل کش `.pyc` روشن شد. فایل `.pyc` نام دیگر بایت‌کد نیست و هر اجرای تعاملی الزاماً چنین فایلی نمی‌سازد.
- توضیح اجرای CPython در Pyodide دیگر آن را از نظر محیط و بسته‌بندی عین نصب دسکتاپ python.org معرفی نمی‌کند.
- چند ادعای مطلق دربارهٔ پیچیدگی دیکشنری، hashable بودن tuple، کارایی list comprehension و مصرف حافظهٔ generator expression دقیق‌تر شدند.
- برای درس آغازین، مسئلهٔ شروع و خودارزیابی ساختاریافته اضافه شد و رندرکننده آن‌ها را نمایش می‌دهد.

### Rust
- تضمین‌های ایمنی حافظه به محدودهٔ Safe Rust نسبت داده شدند.
- متن اکنون صریح می‌گوید کد unsafe، رابط‌های FFI و باگ‌های منطقی همچنان به بررسی نیاز دارند.
- وعده‌های قطعی «صفر هزینهٔ زمان اجرا» و هم‌سرعت‌بودن همیشگی با C/C++ حذف شدند.

### لینوکس و ترمینال
- راهنمای Live USB دیگر تضمین نمی‌کند که «هیچ‌چیز روی دیسک نوشته نمی‌شود»؛ تفاوت اجرای موقت با نوشتن دستی روی پارتیشن‌ها توضیح داده شده است.
- خاموش‌کردن Secure Boot دیگر به‌عنوان راه‌حل پیش‌فرض پیشنهاد نمی‌شود.
- راهنمای Dual Boot دربارهٔ BitLocker و کلید بازیابی هشدار می‌دهد.
- پیش‌نیاز نسخهٔ ویندوز برای `wsl --install` مشخص شد.
- راهنمای `ps`، `kill`، `killall` و `lscpu` واقعیت محیط مرورگر را منعکس می‌کند: فهرست پردازه‌ها شبیه‌سازی‌شده است و مرورگر مدل و معماری واقعی CPU را در اختیار این اپ نمی‌گذارد.
- شمار مأموریت‌های آموزش ترمینال در راهنمای `man learn` از ۱۴ به ۲۸ اصلاح شد.

### API و کیفیت خودکار
- محدودیت بدنهٔ JSON اکنون بر اساس تعداد بایت‌های UTF-8 اعمال می‌شود، نه `string.length` که در جاوااسکریپت تعداد واحدهای UTF-16 را می‌شمارد.
- بدنه به‌صورت stream خوانده می‌شود؛ محدودیت حتی وقتی `Content-Length` موجود نیست یا قابل اتکا نیست بررسی می‌شود.
- UTF-8 نامعتبر و JSON نامعتبر پاسخ جداگانه می‌گیرند.
- تست‌های رگرسیون برای محتوای آموزشی، شناسه‌ها، سرنخ‌ها، پاسخ آزمونک و اندازهٔ واقعی بدنهٔ API به CI افزوده شدند.

## منابع فنی برای اصلاح‌های حساس

- Python، کش بایت‌کد: [Python 3.12 import system](https://docs.python.org/3.12/reference/import.html#cached-bytecode-invalidation)
- Python، فایل‌های کامپایل‌شدهٔ ماژول: [Python 3.12 tutorial](https://docs.python.org/3.12/tutorial/modules.html#compiled-python-files)
- Rust، مرز Safe و Unsafe: [The Rust Programming Language, Unsafe Rust](https://doc.rust-lang.org/book/ch20-01-unsafe-rust.html)
- Ubuntu، نصب کنار Windows و BitLocker: [Install Ubuntu Desktop](https://ubuntu.com/desktop/docs/en/latest/tutorial/install-ubuntu-desktop/)
- Microsoft، پیش‌نیاز `wsl --install`: [Set up a WSL development environment](https://learn.microsoft.com/en-us/windows/wsl/setup/environment)

## حفاظت از دادهٔ پیشرفت

هیچ شناسهٔ درس پایتون، شناسهٔ مأموریت لینوکس یا کلید ذخیره‌سازی پیشرفت تغییر داده نشده است. تغییرهای اسکیمای پایتون فقط فیلدهای اختیاری `problem` و `selfCheck` را اضافه می‌کنند.

## محدودیت‌های این دور

- بازنویسی سراسری تمام متن‌های فارسی، رشته‌های UI، کامنت‌ها و مستندات هنوز یک ممیزی جداگانه می‌خواهد؛ این کامیت نباید به‌عنوان «پاک‌سازی کامل همهٔ فارسی مخزن» معرفی شود.
- محتوای علمی گستردهٔ تمام فصل‌های AI، Rust، PowerShell و لینوکس در این دور از نو نوشته نشده است.
- تست خودکار، کیفیت ساختاری و چند رگرسیون مشخص را می‌سنجد؛ جایگزین بازبینی انسانیِ همهٔ درس‌ها یا آزمون با دانش‌آموز واقعی نیست.
