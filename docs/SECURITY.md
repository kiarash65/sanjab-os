# مدل تهدید و سیاست امنیتی — Security Threat Model (v2.0.0)

> سان‌جاب‌او‌اس یک محصول آموزشی/سرگرمی فارسی است. این سند صادقانه می‌گوید چه چیزی کجا اجرا می‌شود، داده‌ها کجا می‌مانند و چه چیزهایی هنوز «حالت production سخت‌گیرانه» ندارد.

## ۱. چه چیزی کجا اجرا می‌شود؟ (What runs where)

| لایه | کجا اجرا می‌شود | نمونه‌ها | می‌بیند چه؟ |
|------|------------------|----------|--------------|
| **OS Shell (مرورگر)** | کاملاً در مرورگر کاربر | بوت، دسکتاپ، window manager، رجیستری اپ‌ها، ترمینال آموزشی، آکادمی‌ها، بازی‌ها، آفیس | localStorage/IndexedDB مرورگر کاربر |
| **Runtime adapters (مرورگر)** | در مرورگر کاربر | مفسر mini-python (آفلاین)، سنجابی، JS در Web Worker، شبیه‌ساز v86 (WASM، کرنل واقعی Alpine guest) | کدی که خود کاربر می‌نویسد |
| **Face AI (مرورگر)** | در مرورگر کاربر | face-api.js روی فریم‌های دوربین | فریم دوربین فقط محلی پردازش می‌شود |
| **Server API routes (Node/Bun)** | سرور سان‌جاب‌او‌اس | `/api/tutor`، `/api/scores` | فقط بدنهٔ درخواست HTTP |
| **Sandbox gateway (Caddy)** | زیرساخت میزبان | `Caddyfile` روی پورت ۸۱ → `localhost:3000` | ترافیک HTTP عمومی |
| **هوش‌یار (کاربر→سرویس بیرونی)** | مستقیم از مرورگر کاربر به سرویس انتخابی | OpenAI / OpenRouter / Groq / DeepSeek / Claude / GLM | کلید API کاربر + متن چت |

**قانون کلیدی:** هیچ فریم دوربینی، هیچ فایل کاربری و هیچ کلیدی از مرورگر به سرور سان‌جاب‌او‌اس فرستاده نمی‌شود. سرور فقط دو مسیر محدود دارد: پراکسی tutor و جدول امتیازها.

## ۲. قوانین نگهداری اطلاعات اعتبار (Credential handling)

- کلید API هوش‌یار و توکن گیت‌هاب **فقط در مرورگر خود کاربر** ذخیره می‌شوند (`localStorage`: کلیدهای `pengo-ai-cfg-v1` و `pengo-gh-token-v1`) و درخواست‌ها مستقیم از مرورگر به سرویس مقصد زده می‌شوند — سرور سان‌جاب‌او‌اس هرگز در این مسیر واسطه نیست و کلیدی دریافت یا ذخیره نمی‌کند.
- شناخته‌شده و صادقانه: ذخیره در localStorage در برابر XSS هم‌مبدأ آسیب‌پذیر است (AUDIT-007). کاهش‌دهنده‌های برنامه‌ریزی‌شده: حالت فقط-نشست (session-only)، نمایش ماسک‌شده، توکن کم‌دسترسی (fine-grained read-only PAT).
- پیشنهاد به کاربران: توکن گیت‌هاب را با کمترین scope بسازید و پس از استفاده باطل کنید؛ کلید API را از داشبورد سرویس‌دهنده و با سقف هزینه بگیرید.
- کلیدهای API هرگز در ریپو/issue/log قرار نمی‌گیرند. در CI فقط از `GITHUB_TOKEN` و repository secrets استفاده می‌شود.

## ۳. حریم خصوصی دوربین (Camera privacy)

- همهٔ اپ‌های بینایی (تشخیص چهره، قدسنج و وزن‌یاب، ماشین زمان چهره) فریم‌های دوربین را **۱۰۰٪ محلی در مرورگر** با face-api.js پردازش می‌کنند.
- هیچ تصویر، فریم، لندمارک یا نتیجه‌ای به هیچ سروری (از جمله سرور خود پروژه و سرویس‌های مدل) upload نمی‌شود — هیچ upload endpoint هم وجود ندارد.
- دسترسی دوربین فقط با اقدام صریح کاربر (دکمهٔ روشن‌کردن دوربین) و فقط در بستر HTTPS یا localhost ممکن است (نیازمندی مرورگر برای `getUserMedia`).
- اپ «ماشین زمان چهره» شبیه‌سازی ترکیبی روی canvas با لندمارک‌هاست — خروجی آن برچسب «synthetic» دارد و ادعای پیش‌بینی واقعی سن نیست.

## ۴. سیاست بارگذاری مدل‌ها (Model loading policy)

- مدل‌ها فقط از CDN های پین‌شده و فقط با اقدام صریح کاربر بارگذاری می‌شوند؛ هیچ دانلود خودکار در پس‌زمینه انجام نمی‌شود.
- URL های دقیق (مستند در AUDIT-009):
  - `https://cdn.jsdelivr.net/npm/face-api.js@0.22.2/dist/face-api.min.js`
  - `https://cdn.jsdelivr.net/gh/justadudewhohacks/face-api.js@master/weights`
- شناخته‌شده: ref وزن‌ها (`@master`) متغیر است — پین به commit SHA + SRI در لیست کارهای بعدی است.
- فایل‌های v86 (bzImage/initramfs/ISO/`v86.wasm`) آفلاین از `public/v86/` سرو می‌شوند؛ اتصال شبکهٔ داخل guest به‌صورت پیش‌فرض خاموش است و فقط با انتخاب کاربر (`network_relay_url: 'fetch'`) فعال می‌شود.

## ۵. محافظت‌های API (API protections)

| مسیر | محافظت فعلی | وضعیت صادقانه |
|------|--------------|----------------|
| `POST /api/tutor` | cap طول سؤال (500 نویسه)؛ rate limit + نقش `system` + timeout در drop کد 2.0 | `In Progress` (AUDIT-006) |
| `POST /api/scores` | اعتبارسنجی شکل داده + بازهٔ 0..1e9؛ رجیستری بازی‌ها + rate limit در drop کد 2.0؛ تأیید رمزنگاشتی امتیاز انجام نمی‌شود | `In Progress` (AUDIT-005) |
| `GET /api/scores` | فقط خواندن top-20 هر بازی | بدون rate limit فعلاً |
| `/api` (سلام) | بدون دادهٔ حساس | کم‌اهمیت |

امتیازهای جدول جهانی یک ویژگی سرگرمی‌اند — نه رکورد رسمی؛ spoofing راحت ممکن است تا زمانی که سمت سرور از ادعای کلاینت بازسازی کامل شود، و حتی آن‌وقت هم بدون امضا، تأیید رمزنگاشتی وجود ندارد.

## ۶. ذخیره‌سازی داده (Data storage)

| لایه | کجا | محتوا |
|------|------|-------|
| `localStorage` (`sunjob-os-v1`) | مرورگر کاربر | تنظیمات دسکتاپ (والپیپر، رنگ، حالت شب/روز) |
| `localStorage` (`pengo-fs-v2`) | مرورگر کاربر | فایل‌سیستم مجازی پنگوئن‌اواس (فایل‌ها/پوشه‌های کاربر) |
| `localStorage` (`pengo-*`) | مرورگر کاربر | یادداشت‌ها، اسلایدها، صفحه‌گسترده‌ها، چت هوش‌یار، رکورد بازی‌ها، اسم بازیکن، بوکمارک/تاریخچهٔ سفربُر |
| `localStorage` (`pengo-ai-cfg-v1`، `pengo-gh-token-v1`) | مرورگر کاربر | کلیدهای ادغام کاربر — بخش ۲ را ببینید |
| IndexedDB | مرورگر کاربر | طراحی‌شده برای وضعیت VM و بکاپ/بازیابی — **در snapshot فعلی پیاده‌سازی نشده** (برنامهٔ 2.0) |
| SQLite (`db/custom.db`) | سرور | فقط جدول امتیازهای جهانی (بدون حساب کاربری/ایمیل) |

## ۷. اعلام صادقانه (Disclosure)

سان‌جاب‌او‌اس در نسخهٔ 2.0.0 هنوز یک استقرار production چندکاربرهٔ harden شده **نیست**:

- بدون احراز هویت کاربر، بدون HTTPS تحمیلی در خود اپ، بدون WAF/limiting در سطح gateway عمومی.
- امتیازها ضد-spoof نیستند؛ tutor proxy به امنیت کلید/زیرساخت میزبان وابسته است.
- چرخهٔ زندگی secret ها (ابطال توکنِ فاش‌شده در تاریخچهٔ چت — AUDIT-010 — و پاک‌سازی تاریخچه) پیش از انتشار عمومی الزامی است.
- برای استقرار واقعی: پشت reverse proxy با TLS، rate limit در لایهٔ شبکه، و پایش لاگ‌ها قرار گیرد.
